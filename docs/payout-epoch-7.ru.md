# Выплаты за эпоху 7: обычный сценарий

Проверки уже встроены в команды. Отдельно вводить doctor, dry-run, backup,
копировать UUID/plan и запускать reconcile в обычном сценарии не нужно.
Существующие алиасы вызывают обновлённые скрипты, поэтому повторно загружать
алиасы не требуется. Если функций ещё нет в текущей оболочке, из корня проекта:

```bash
source ./scripts/aliases.sh
```

## 1. Посмотреть расчёт

```bash
balance_mina --epoch 7
```

Если личного алиаса balance_mina нет, используйте `mina_calc --epoch 7`.
Команда включает туннель, проверяет архив/валидатор и готовит неизменяемый план.
Она не отправляет деньги. Повторный расчёт возвращает сохранённый план.

## 2. Подтвердить выплаты

```bash
mina_pay --epoch 7
```

Команда сама создаёт резервную копию, проверяет архив/валидатор/баланс/nonce,
запрашивает подтверждение и пароль, отправляет только недостающие платежи,
закрывает кошелёк, ждёт подтверждения, сверяет учёт и сохраняет итоговую копию.
Результат «Сверка завершена, учёт сохранён» означает завершение цикла.
При доказанном неуспешном платеже его сумма остаётся обязательством и это
показывается отдельно; она не считается выплаченной.

Ожидание по умолчанию — до часа (`AUTO_SETTLE_WAIT_SECONDS`, либо явный
`--wait-seconds`). Таймаут означает pending и код выхода 2, не успех.
Ctrl+C означает код 130: журнал сохраняется, операция не отменяет уже
отправленные транзакции. В обоих случаях позже повторите **ту же команду**:

```bash
mina_pay --epoch 7
```

Повторная отправка неизвестной транзакции запрещена. Если доказательств её
результата пока нет, учёт не закрывается и деньги не посылаются второй раз.

## 3. Вывести учтённый доход

После завершения выплат сумма подставляется из БД автоматически:

```bash
mina_withdraw
```

Адрес берётся из WITHDRAW_TO_ADDRESS в config.yml. Проверки, резервные копии,
ожидание и сверка тоже автоматические; нужны только подтверждение и пароль.
В таблице видны комиссия валидатора, свои награды, расходы и уже сделанные
выводы. Начальный учёт ведётся с эпох 6 и 7. Уже перечисленные своим адресам
выплаты делегаторам повторно не включаются. Комиссия нового вывода вычитается
из доступного дохода. `mina_withdraw --dry-run` показывает расчёт без отправки.

При таймауте повторите `mina_withdraw`. Незавершённый автоматический вывод
найдётся без ручного ввода UUID. После успешного вывода повторная команда
ничего не отправит, пока не появятся новые учтённые начисления.

Ручной выбор суммы остаётся доступен через `--amount` и тоже записывается в БД.

Для намеренно НОВОГО вывода той же суммы после завершения предыдущего:

```bash
mina_withdraw --amount 12.345678901 --new-operation
```

При прерывании или ошибке такого нового вывода используйте напечатанную
команду продолжения с --operation-id. Не повторяйте --new-operation: этот флаг
означает намеренное создание ещё одного перевода.

Сохранились продвинутые команды doctor/status/reconcile и явные --plan /
--operation-id для диагностики и неоднозначных случаев. Они не нужны для
обычной успешно завершённой выплаты. Низкоуровневый payout_cli.py send/withdraw
без --complete оставляет прежнее ручное управление; пользовательские скрипты
send_payout.py/withdraw.py и алиасы включают полный цикл автоматически.

## Неснятая комиссия прежних эпох

Она не прибавляется к начислениям делегаторов следующей эпохи: выплаты считаются
по наградам выбранной эпохи и записанным остаткам, а не по всему балансу кошелька.
Доход владельца учитывается отдельно в БД. Баланс кошелька общий и используется также
для переводов и сетевых комиссий; он может включать ещё не распределённые
награды. Вывод резервирует записанные обязательства, но не вычисляет все будущие
обязательства из нерассчитанных эпох. Поэтому весь остаток не объявляется
комиссией и не выводится автоматически.
