# Настоящие пакетные выплаты Mina — Devnet

Изолированный режим проверки: одна подписанная zkApp-транзакция переводит MINA
нескольким получателям. Контракт разворачивать не требуется. Один пакет имеет
один nonce, один хеш и одну сетевую комиссию. Размер пакета — от 1 до 30
получателей; реальное число сегментов дополнительно проверяет o1js.

Этот CLI работает только в Devnet. Для основной сети предусмотрен отдельный
[mainnet batch CLI](../docs/BATCH_MAINNET.md) с архивной сверкой и отдельным журналом.
Не переносите в Devnet-каталог производственный приватный ключ.

[Результаты публичного Devnet-теста](../docs/BATCH_DEVNET_VALIDATION.md):
два перевода по одной nanomina, Applied + 3 блока, намеренная потеря ответа,
восстановление в новом процессе и ноль повторных отправок.

## Запуск

Нужен Node.js >=22.19.5. Из корня проекта:

```bash
npm ci --prefix batch-pay --ignore-scripts
node batch-pay/cli.mjs init
```

Пополните выведенный адрес тестовыми MINA через официальный
[Devnet faucet](https://faucet.minaprotocol.com/).

Создайте приватный файл `batch-pay/.state/devnet/recipients.json`:

```json
[
  {"address": "B62...полный адрес первого получателя...", "amount": "1"},
  {"address": "B62...полный адрес второго получателя...", "amount": "1"}
]
```

`amount` и `--fee-nano` задаются строками целых nanomina: `1` = 0.000000001 MINA.
По умолчанию получатель должен уже существовать. Для нового тестового аккаунта
можно явно добавить `"create": true`: план покажет дополнительную плату создания
1 tMINA. Она включается в общую стоимость и защищается условием отсутствия аккаунта.

```bash
node batch-pay/cli.mjs plan --file batch-pay/.state/devnet/recipients.json --operation test-001 --batch-size 2 --fee-nano 100000000
node batch-pay/cli.mjs status
node batch-pay/cli.mjs send --plan ID_ИЗ_ПЛАНА
node batch-pay/cli.mjs resume --plan ID_ИЗ_ПЛАНА
```

`send` показывает получателей, суммы, комиссию и спрашивает подтверждение.
`resume` только сверяет. Отображаются полный хеш, nonce и текущие/нужные
подтверждения. Завершение — Applied и 3 блока после включения.

## Прерывание и повторный запуск

Подписанный пакет и хеш записываются в отдельный SQLite-журнал **до** сетевого
запроса. Непосредственно перед запросом сохраняется `unknown`. Отправка использует
ровно один HTTP POST: встроенные повторы отправки из o1js не используются.

Если ответ потерялся, повторный запуск ищет тот же хеш в связной цепочке и пуле.
Он не создаёт другую транзакцию, не меняет nonce и не повторяет отправку.
Отсутствие в пуле не доказывает неуспех. Если запрос вообще не дошёл, операция
останется неопределённой и потребует отдельной проверки. Автоматического сброса
или разблокировки зарезервированного nonce нет.

Повтор операции с тем же именем и теми же параметрами возвращает прежний план.
Изменить сохранённый план нельзя. Один кошелёк не может одновременно начать
две незавершённые операции. Резервирование nonce и захват отправки атомарны
между процессами. Перед следующим пакетом заново проверяются предыдущие выплаты.

Журнал и тестовый ключ находятся в `batch-pay/.state/devnet/`, исключены из Git.
Сохраните эту директорию: удаление журнала уничтожит локальную защиту от повторов.
Она не связана с `.payout-state/journal.sqlite3` основного проекта.

## Проверки и ограничения

```bash
npm test --prefix batch-pay
```

Тесты используют реальный `Mina.LocalBlockchain` с проверкой лимитов,
настоящими подписями и изменением балансов; SNARK-доказательства выключены,
поскольку переводы авторизуются подписями. Проверяются 30 существующих/новых
получателей, атомарность начислений при отказе, точные комиссии и nonce,
потеря соединения до/после принятия, повтор, конкурентный запуск, смена цепочки,
реорганизация, неверные доказательства и устаревший nonce.

Публичная сетевая квалификация запускается отдельно, не из `npm test`.
`test/devnet-live.mjs lost-response` отправляет микро-пакет подготовленным
тестовым адресам и намеренно теряет ответ HTTP после POST. `verify` в новом
процессе проверяет точные изменения балансов, подтверждения и отсутствие
повторной отправки. Для неё нужны подготовленные приватные Devnet fixtures.

Сверка пока ограничена последними 290 блоками Devnet. **Если любая старая
операция вышла из этого окна, следующие отправки этого кошелька блокируются**:
старое подтверждение без свежего доказательства не считается достаточным.
Для производственного использования ещё нужны архивный zkApp-адаптер,
согласование с существующим учётом выплат и безопасный способ подписывать
транзакции существующим кошельком. Они намеренно не включены в текущие алиасы.

Закреплён o1js 3.1.0. Два внутренних интерфейса (проверка лимитов и сериализация
GraphQL-команды) покрыты тестами; обновление библиотеки требует их перепроверки.

Основания: [Account Updates](https://docs.minaprotocol.com/zkapps/tutorials/account-updates),
[лимит Mesa](https://github.com/MinaProtocol/MIPs/blob/main/MIPS/mip-0009-increase-zkapp-account-update-limit.md).
